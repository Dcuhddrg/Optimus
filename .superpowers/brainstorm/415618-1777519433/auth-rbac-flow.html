登录认证 + RBAC 推荐流程

第一版建议把身份认证、用户同步、权限判定拆成清晰边界。

Runtime Flow
1. Login Form

单表单输入 username/password。username = admin 走本地认证，其余走 LDAP。

2. Auth Service

本地管理员校验密码哈希；LDAP 用户按 user_filter 搜索并 bind 校验。

3. User Sync

LDAP 首登自动创建本地用户，后续同步显示名、邮箱、状态外字段。

4. JWT + RBAC

签发短期 Bearer JWT；API 中间件解析用户角色并用 Casbin/权限表拦截。

Admin Area

用户管理、角色管理、角色授权、LDAP 配置、审计日志。菜单/API 权限点由后端 seed，不在第一版页面新增删除。

A

推荐：完整登录 + 可控 RBAC

身份接入、用户同步、角色授权、菜单/API 权限、LDAP 配置和审计一起闭环，但避免动态新增菜单/API 权限。

B

缩小版：先登录，权限简化

先做本地 admin + LDAP + JWT，只做 admin/user 两级角色；更快，但不符合你选择的完整 RBAC。

C

扩展版：完整权限元数据管理

菜单和 API 权限也可在线新增删除；最灵活，但会显著增加前后端复杂度和误配置风险。
