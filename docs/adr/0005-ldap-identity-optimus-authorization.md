# ADR-005：LDAP 管身份，Optimus 管授权

- 日期：2026-11-06。
- 状态：已由用户确认（"ldap 只负责同步用户信息，实际权限分配和管控是在 optimus 上处理"）；实施跟踪见 [#80](https://github.com/Dcuhddrg/Optimus/issues/80)。
- 现行设计：[用户管理设计](../design/2026-11-06-user-management-design.md)。

## 背景

除内置 `admin` 外，Optimus 的用户都通过 LDAP 登录，首次登录时自动建账号并绑定 `user` 角色。审批流需要确定审批人，因此需要先决定：角色、审批资格、组织关系这些数据，由 LDAP 提供还是由 Optimus 自己维护。测试环境的目录里没有组，也没有 `manager` 属性。

## 决定

- LDAP 只负责身份：认证（LDAP 用户的密码只在 LDAP 校验），以及用户资料（用户名、显示名、邮箱、部门）的同步。LDAP 用户的这些资料以 LDAP 为准，在 Optimus 中只读。
- 身份按目录中不可变的标识匹配，不按用户名匹配。标识属性只能从白名单（`entryUUID` 等由服务器生成的唯一属性）中选择，并在登录和同步时检测重复。uid 被另一个人复用时会被识别为冲突，新人不会继承旧人的权限；存量账号也必须读到有效的标识才能补写。
- 目录中已删除的用户自动停用，但只针对能确认已删除的账号。要同时满足三个条件：账号已绑定目录标识；在整个目录（从目录根起）都查不到；自上次同步成功以来 LDAP 配置没有改动。仍在目录中、只是不在同步范围内的人，以及无法确认的人，都要管理员确认后才停用。已有账号绑定目录标识后，不能再修改标识属性。
- 授权全部在 Optimus：系统角色、审批角色、项目成员和项目负责人都由 Optimus 维护。不做 LDAP 组到角色的映射，部门字段也不参与授权。人员类型（员工或第三方，取自 `employeeType`）是唯一会影响授权规则的同步字段：第三方新建时不给默认角色，不能持有审批角色或担任项目负责人。第三方的有效期和对接人由 Optimus 维护，缺失或到期即无权限。第三方账号同样建在 LDAP 中，不另建本地账号。
- 授权的改动在下一个请求就生效，不等用户重新登录。
- 用户状态由 Optimus 决定。目录中已删除的用户在同步时被停用；用户重新出现在目录中时不会自动启用。Optimus 也可以停用一个仍在目录中的用户。

## 考虑过的方案

- **LDAP 组映射角色**：权限和人员一起在目录里维护，Optimus 里不需要再做分配。但审批角色、项目负责人都是 Optimus 的业务概念，每次调整都要找目录管理员；两边都能影响权限时，排查也要看两处。另外测试目录里没有组。
- **LDAP 提供组织关系（`manager`）用于审批**：可以支持按"直属主管"审批，但目前没有数据。保留为以后的方向，届时这些数据也只作为资料同步，审批规则仍在 Optimus 配置。

## 代价

- 新同步进来的用户，需要管理员在 Optimus 中分配角色。为此要增加"从 LDAP 同步"，让管理员能在用户首次登录前就看到并配置他。
- 权限即时生效，每个请求都要取用户的状态和角色。这里用进程内缓存控制开销，靠版本号防止并发请求把旧值写回缓存。多实例部署时需要改成共享缓存或广播失效。
- 现有 LDAP 用户补写目录标识之前，如果已经发生过 uid 复用，事后无法识别。
- 这里有意与 GVA 不同：GVA 默认不检查已登录用户是否被禁用，相关代码被注释掉了。
