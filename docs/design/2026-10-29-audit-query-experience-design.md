# 审计日志查询与阅读体验

- 关联：#28；用户已确认第一批范围并授权推进。
- 状态：第一批用户验收通过并授权提交 PR、合入 main；交付与验证记录见 #28。

## 方案与范围

沿用现有系统审计页面及 CSS Modules，不新增导航、依赖或数据库字段。列表展示时间、操作人（快照名，缺失时显示 ID/未知）、本地化操作、资源对象、结果、IP；原始操作码、用户代理和原始详情在可展开的详情区保留。未知枚举回退原值，历史空详情显示未记录，不推测变更内容。

接通现有后端 page/pageSize/total/items；默认 20 条，支持切换每页条数和前后翻页。查询表单提供时间、操作人 ID、操作、资源类型、结果及详情关键词；草稿与已应用条件分离，提交或重置回第一页，每页条数变化回第一页。时间输入转带时区 ISO 字符串并校验先后。新查询取消旧请求，忽略旧响应，避免错误数据覆盖；加载、失败/重试和空状态分开。数据减少导致页码越界时回到有效末页。

导出复用相同的已应用筛选，不使用当前分页；提示后端现有最多 10000 条的限制。下载走模块 API 和共享认证请求能力，校验 HTTP 状态与 text/csv 类型，JSON/HTML 错误不保存成 CSV；保留 #27 的 401 规则。下载结束释放对象 URL。导出失败单独展示，不清空查询列表。

## 实施边界

不在本批补后端事件覆盖、变更前后值、登录账号线索或审计写入失败策略；这些作为后续记录质量改造在 [#36](https://github.com/Dcuhddrg/Optimus/issues/36) 待评估。不迁移 #18 的响应 envelope，不改保留期和部署配置。本批复用现有后端能力，不修改后端代码。当前菜单权限不能代表导出 API 权限，入口由服务端鉴权；403 明确提示无导出权限。

## 验证

使用现有 Vitest/jsdom、真实 React 页面和请求封装，模拟 fetch 边界。覆盖分页、筛选重置、时间转换及无效输入、请求竞争、详情/空/失败/重试、未知枚举、中英文、CSV 筛选一致、下载失败与认证语义。回归 #27 并执行前端构建；既有审批链测试缺失单独记录，不顺手修复。真实浏览器和认证后端验收另行记录。
