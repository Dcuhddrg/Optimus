# 前端开发与复用规范

- 页面与组件负责交互和展示；请求放在 `web/src/api/` 的模块函数，公共 HTTP 行为集中在 [client.ts](../../web/src/api/client.ts)。插件如新增 API，按插件边界组织并复用公共请求能力。避免组件自行拼接认证或绕过服务端校验。
- 优先检查并复用 `web/src/components/`、`web/src/utils/` 和相关模块已有能力；不存在的工具不能凭上游文档假定可用。通用能力确有重复需求时再提取，避免为单次使用新增抽象或依赖。
- React 组件使用 PascalCase，变量和函数使用 camelCase；文件命名、状态管理与路由组织沿用所在模块的现有约定，不为统一命名批量重命名存量文件。共享状态优先沿用项目已有 Context；仅组件内使用的状态放在组件或相关 hook 中。
- 样式沿用现有 CSS、组件和主题变量；优先复用现有样式与设计，不照搬上游 UnoCSS、Element Plus 或主题类名。避免无必要的内联样式；必要的动态值可局部使用。
- 路由及页面变更考虑认证和已有权限入口；新增页面覆盖加载、空数据、失败及权限不足等状态。需要改善性能时依据实际列表规模、网络及渲染瓶颈选择分页、懒加载或其他优化，不假定当前已经具备对应能力。
- 导出接口函数和复杂交互在类型无法表达意图时补充必要说明；前端类型应与真实响应一致，不用类型断言掩盖协议差异。
