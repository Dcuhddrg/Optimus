# 前端壳层与 System 导航优化设计

## 背景

当前 Optimus 前端已经具备基础后台壳层，但整体观感偏粗糙，尤其左侧导航里 `system` 分组的视觉层级与其他导航项不一致：

- `Dashboard` 是一级直链，`System` 是单独的折叠块，信息结构像两套组件拼在一起
- `System` 子项主要依赖额外卡片感来区分，展开后会显得像后加的一块区域
- 顶部栏、侧栏、内容区的表面语言不统一，边框、背景、阴影和留白节奏存在割裂
- 现有暖色基调是可用的，但层级表达过重，导致“简陋”与“突兀”同时出现

本次目标不是整站重做，而是在不改业务语义的前提下，把后台壳层统一成一套更轻、更顺、更克制的界面骨架。

## 目标

- 让左侧导航成为统一的导航面板，而不是“普通导航 + 突出 system 扩展栏”的拼接结构
- 让 `System` 成为自然嵌入的二级导航分区，弱化突兀感
- 统一侧栏、顶部栏、页面内容区的壳层语言
- 保留当前暖色基调，但降低装饰强度，走“轻量极简 + 柔和面板”的方向
- 不改变现有路由、权限判断、登录态和页面业务流程
- 保持改动范围集中、可回滚、易验证

## 非目标

- 不重做登录页视觉
- 不新增前端依赖或设计系统框架
- 不调整后端接口、路由结构、权限模型或菜单权限逻辑
- 不把所有业务页面都重构成新的组件体系
- 不扩展为全站品牌升级或插画、图标系统重做

## 已评估方案

### 方案 A：轻改样式

仅修改现有 CSS，不调整导航结构。

优点：

- 风险最低
- diff 最小

缺点：

- `System` 依然保留现有结构上的割裂感
- 只能降低突兀，不能真正解决层级不统一问题

### 方案 B：壳层重整

小幅调整 `SideNav` 与 `AppShell` 结构，同时重写主要壳层样式，让导航、顶栏、内容区共用一套表面语言。

优点：

- 能直接解决 `System` 的补丁感
- 改动集中，影响面可控
- 足以明显提升整体精致度

缺点：

- 比纯 CSS 调整多一层结构改动
- 需要补做窄屏和激活态检查

### 方案 C：壳层系统化

在方案 B 基础上继续抽离更通用的壳层 token、section pattern 和页面骨架规则，顺手统一更多页面内部组件。

优点：

- 长期维护更整洁
- 可作为后续页面持续升级基础

缺点：

- 本次任务会明显扩 scope
- 容易从“优化壳层”演变成“前端局部重构”

## 选型结论

采用 `方案 B：壳层重整`。

原因：

- 用户目标是“优化简陋感”和“削弱 system 扩展栏突兀感”，核心问题在壳层结构和层级语言，而不只是颜色或圆角
- 方案 B 可以在不引入新依赖、不重写业务页面的前提下，完成最有价值的结构与样式修正
- 方案 C 的收益更偏长期，不适合这次“顺手统一”的任务边界

## 设计方向

本次视觉方向采用：`轻量极简 + 柔和面板`

具体原则：

- 保留暖色，但改用更低对比的表面层级
- 减少“块状高亮 + 浮层阴影”的依赖，改用细边框、留白、浅背景和稳定节奏表达结构
- 导航、顶栏、内容画布统一为同一家族的圆角、边框透明度和背景材质
- 让视觉重点从装饰切换到信息组织本身

## 范围

本次实现主要覆盖以下文件或等价落点：

- `web/src/components/nav/SideNav.tsx`
- `web/src/components/nav/SideNav.module.css`
- `web/src/layout/AppShell.tsx`
- `web/src/layout/AppShell.module.css`
- `web/src/style/index.css`

必要时可少量调整系统页面样式文件，使页面头部和内容容器与新壳层保持一致，但不应扩大为系统页内容重构。

系统页协调的优先落点应为：

- `web/src/components/page/PageHeader.tsx`
- `web/src/components/page/PageHeader.module.css`
- 少量系统页面模块样式

考虑到当前并非所有系统页都共用 `PageHeader`，若页面头部不一致主要来自既有页面模块差异，应优先在对应的 `web/src/view/system/*.module.css` 中做小范围协调。

不应把这一步扩展为逐页内容布局重写。

## 导航结构设计

### 目标状态

左侧应表现为一个完整的导航面板，而不是一个普通链接加一个额外展开块。

### 导航层级

- 品牌头部保留，但弱化为轻识别区
- 一级导航项统一使用同一套布局与交互规则
- `System` 作为一级分区入口，内部承载二级页面链接
- 二级项通过轻缩进、浅背景和局部分隔表现层级，不再依赖明显的独立卡片

### `System` 分区行为

- 保留折叠/展开能力
- 当当前路径位于 `/system` 下时，`System` 自动处于展开状态
- 非系统页允许用户手动折叠
- 当前路径位于系统页时，同时高亮 `System` 分区和对应子项，形成清晰的“父激活 + 子激活”关系

### 结构调整建议

允许在 `SideNav.tsx` 中引入更清晰的语义分块，例如：

- 品牌区
- 一级导航区
- `System` 分区标题行
- `System` 子导航容器

但不应引入新的复杂组件抽象，保持单文件可读性。

## 侧栏视觉语言

### 品牌区

- 缩小品牌块视觉重量
- 品牌标识保留，但降低渐变和高对比强调
- 标题、副标题与导航之间拉开更稳的节奏

### 一级导航项

- `Dashboard` 与 `System` 使用一致的行高、圆角、内边距和文本权重
- hover 采用浅色面变化，不使用厚重阴影
- active 使用更克制的底色和边框高亮

### 二级导航项

- 采用更短的垂直节奏和更轻字体权重
- 通过轻缩进和局部背景形成内嵌感
- 子项 active 可比父项更明确，但整体仍保持克制

### 分区边界

- 允许通过局部浅面板或细边框把 `System` 子项包进同一块区域
- 该区域必须看起来像父项自然展开后的内部层，而不是独立漂浮卡片

## 顶部栏设计

### 目标状态

顶部栏从“多个离散控件并排”收敛为更薄的工作条，与侧栏和内容画布处于同一壳层体系。

### 结构要求

- 左侧保留现有壳层标题区，但仅做样式压缩与层级整理
- 不新增路由级标题映射机制，不引入新的页面上下文元数据系统
- 弱化过度装饰性的 eyebrow 表达，保留必要的层级提示
- 右侧的语言切换、用户信息、退出操作统一为一组轻控件

### 视觉要求

- 压低整体高度与垂直占用
- 统一按钮、badge、切换控件的圆角、边框透明度和背景透明度
- 避免顶部栏比内容区更抢眼

## 页面外壳设计

### 总体关系

- 页面应有“外层背景 + 内层内容画布”的明确关系
- 侧栏、顶栏、主内容区共享同一套背景氛围和材质语言

### 内容画布

- 主内容区维持舒适留白
- 页面主体可用更统一的圆角、边框和浅层表面表达
- 避免当前“导航一套风格，内容一套风格”的断裂

### 页面头部协调

- 系统页已有头部结构应尽量沿用
- 如需微调，仅调整间距、标题区与内容区的壳层协调关系
- 不重写页面内部业务卡片、表格或表单结构

## 样式令牌策略

不引入新的设计系统，但允许在现有全局样式中补齐更稳定的壳层 token。

建议统一的 token 类别：

- 背景层级
- 表面层级
- 边框透明度
- 主文本 / 次文本
- 导航 active / hover 状态
- 壳层圆角
- 壳层阴影或内阴影

原则：

- 优先复用和收敛现有暖色变量
- 新增变量只服务于本次壳层统一，不扩展为庞大主题系统

## 响应式要求

本次不要求完整重构移动端导航，但必须保证：

- 窄屏下侧栏、顶栏和主内容不发生明显错位
- 顶栏右侧控件允许自然换行
- 导航展开态在较窄视口下仍可读，不出现文本严重拥挤

如果现有布局在窄屏下暴露出明显问题，可做必要的局部 CSS 修正，但不扩展为移动端菜单模式重写。

## 实施边界

### 可以调整

- `SideNav` 的内部标记结构
- 壳层样式变量
- 顶栏控件编排和轻量视觉统一
- 页面内容区外层容器样式

### 不应调整

- 路由定义和页面跳转关系
- `useAuth()` 权限判断逻辑
- 菜单权限 code 与可见性规则
- 系统页内部业务逻辑和接口调用

## 验证要求

实现后至少完成以下验证：

- 前端构建通过
- `Dashboard` 页面壳层显示正常
- 非 `/system` 路由下，`System` 分区可手动折叠与展开
- `System Users` 页面中 `System` 父分区与当前子项激活关系正确
- `System Roles`、`LDAP`、`Audit Logs` 页面导航切换正确
- 顶栏控件在常规桌面宽度下布局统一
- 较窄宽度下顶部栏与内容区不出现明显挤压错位

## 风险与注意事项

- `System` 展开态逻辑与当前路径联动，结构改动时要避免误伤现有自动展开行为
- 过度强调“设计感”会重新引入厚重面板和视觉噪音，需要保持克制
- 若系统页局部样式与新壳层反差过大，只做必要协调，不把实现范围扩大到页面内部全面翻新

## 实施完成标准

满足以下条件即可视为本次目标完成：

- `System` 扩展栏不再显得像后加模块，而是自然成为导航中的二级分区
- 顶部栏、侧栏、内容区形成统一壳层语言
- 整体观感比当前更轻、更整洁、更专业
- 无业务行为回归
- 改动集中在预设范围内，验证可复现
