## 本批边界

新增共用 HTTP JSON 响应助手和前端显式 envelope 适配器，首批切换 GET /system/audit-logs 的 JSON 查询。审计导出成功仍是 text/csv；其 JSON 失败也采用已确认的新错误结构。其他模块的成功/失败 payload 保持原状，health/ping/base/ping 不迁移。全量端点清单、调用方及后续批次由 #18 记录；本批不是整个 #18 完成。

审计分页将内部 Service/Store 的 items 映射到 HTTP data.list，不重构业务/持久化 DTO。外层 code/data/msg；成功0、失败7，普通无数据为{}，401为null。保留已有200/400/401/403/404/409/422/500/503等语义。

## 公共层与跨模块错误

前端 apiRequest 保留旧协议；新 apiRequestEnvelope 必须由已迁移模块显式选用，严格检查 code 整数、data 字段存在、msg 字符串，不按对象形状自动切换。data 为null/0/false均原样返回。2xx/code!=0为业务失败，非2xx始终失败；ApiError保留HTTP状态、可用业务码及http/network/protocol/business类别。HTTP错误分支临时兼容msg/message用于提示，不进行成功隐式解包，不自动重试写操作。

后端在JWT之前为明确登记的“方法+规范路由”设置协议标记；只决定这些路由的鉴权错误格式，不全局包裹响应，不按客户端header协商。使用Gin规范化的实际路由前缀，包含默认、自定义、根前缀回归，不能匹配相似路径。JWT/RBAC使用共享失败输出：标记请求输出新envelope，未标记请求仍输出原message。ProjectScope本批不迁移，因为审计组不依赖项目上下文；其旧语义继续回归。

Recovery 对未开始写出的已标记请求返回 JSON500，旧请求保留原空正文500。若响应已开始写出，状态已无法改写，只中止并保留原正文，不追加 envelope；这避免污染部分CSV，但不保证中断的下载完整。审计模块还校验 data.list、total/page/pageSize 与已有记录字段类型，不将畸形分页视作空列表。
